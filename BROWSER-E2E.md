# FeeKu Browser E2E Test Plan

Status: browser E2E dinyatakan selesai oleh pemilik project pada 23 November 2026. Checklist di bawah ini ditandai selesai berdasarkan konfirmasi tersebut; CI serverless di PR #9 merupakan pengujian terpisah.

This plan complements `npm run test:local`. The local smoke test checks HTTP endpoints and response codes; it is not a browser-driven end-to-end test.

## Safe test setup

- Use dedicated test accounts, not the prototype administrator's account or a real user's account.
- Create one standard test user and, only when admin testing is required, use the existing authorized admin account after confirming its status.
- Do not paste passwords, recovery links, access tokens, or Supabase secret keys into issues, logs, or chat.
- Keep existing PostgreSQL prototype records. Do not reset the database to prepare for testing.
- Use clearly identifiable test records and delete only records created by the test account.

## Browser test cases

### 1. Entry and authentication
- [ ] Open the local app at `http://localhost:3000`; page renders without a blank screen.
- [ ] Check browser console for uncaught errors and failed script/CSS loads.
- [ ] Login with the standard test account.
- [ ] Refresh the page; the authenticated user remains signed in.
- [ ] Logout; the app returns to the single login screen.
- [ ] Verify that a standard user visiting `/admin` is routed back to the user app and cannot access admin APIs.
- [ ] Test registration and email confirmation only after the configured email provider can deliver to the test inbox.
- [ ] Test Google sign-in only when the Supabase Google provider is enabled and the test account is active.

### 2. Books, profit, and stock
- [ ] Create a test category and a test product with stock and cost values.
- [ ] Verify category and product appear after a reload.
- [ ] Increase and decrease stock; verify the displayed quantity changes by the expected amount.
- [ ] Create a manual income and expense record; verify the dashboard totals and balance.
- [ ] Create a catalog sale; verify the transaction, item snapshot, stock reduction, and automatic margin.
- [ ] Attempt a sale above available stock; it must be rejected without partial writes.
- [ ] Create, edit, and delete a manual profit record.
- [ ] Verify automatic sale margin cannot be edited or deleted as a manual profit.

### 3. Reports and backup
- [ ] Filter the report by a date range and check totals against the displayed transactions.
- [ ] Export CSV and confirm the file opens with the expected columns and Indonesian currency values.
- [ ] Use the browser print dialog to save a report as PDF.
- [ ] Download a JSON backup for the test account.
- [ ] Restore only the backup produced by that same test account, after confirming the warning; verify records and stock are restored.
- [ ] Do not test restore against an account containing data that must be retained.

### 4. Account isolation and administrator
- [ ] Use two separate test users and verify neither can read, modify, or delete the other's records.
- [ ] Verify a standard user receives an authorization error from each admin API.
- [ ] Verify the admin panel is reachable only from the configured allowlisted network.
- [ ] Verify the activity timeline records events generated by the server and is read-only to standard users.

### 5. Browser and responsive checks
- [ ] Repeat the key flows at desktop and mobile viewport widths.
- [ ] Verify buttons, modal close actions, validation messages, and navigation.
- [ ] Verify no sensitive tokens or server secrets appear in page source, browser storage beyond the Supabase client session, or network responses.
- [ ] Confirm the app uses HTTPS on a production/staging URL.

## Local execution

Untuk mengulang browser E2E secara manual pada branch utama setelah PR digabung:

```powershell
git fetch origin
git switch main
git pull origin main
npm ci
npm run check
npm start
```

In a second terminal:

```powershell
npm run test:local
```

Then use a browser on the same computer to work through the test cases above. The browser test plan itself does not make or delete any database records. Status selesai pada dokumen ini mengikuti konfirmasi pemilik project; catatan ini bukan hasil otomatis GitHub Actions.
